# Orchestrator framework decision (spike, 2026-10-12)

**Recommendation: LangGraph** for [issue #28](https://github.com/AkritiAgarwal09/Data-Science-Capstone-Project/issues/28). It requires fixed stage order, a quality-gate loop capped at three attempts, a separate one-retry rule for stage errors, and a decision log; no LLM chooses routing. LangGraph represents the loop as `proposal → gate → (retry or stop)`. The Agents SDK handles typed LLM output well, but needs an explicit Python loop around separate `Runner` calls for this deterministic routing. [Architecture](architecture.md), [LangGraph Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api), [Agents SDK models](https://openai.github.io/openai-agents-python/models/).

| Criterion | LangGraph | OpenAI Agents SDK |
|---|---|---|
| Capped retry | Conditional edge reads attempt count from state. | Python `for` loop wraps the two agents; SDK turn limits do not encode the quality-gate cap. |
| Shared state | `StateGraph` carries proposal, gate, attempts, and decisions between nodes. | The spike passes the same state explicitly between `Runner.run_sync` calls. |
| Decision logging | Node updates record each decision; optional graph checkpoints can be added later. | Same JSONL decisions; built-in tracing is broader, but the spike disables its default export for the non-OpenAI provider. |
| Effort to run | More graph wiring, then routing is visible in edges. | Less setup for `Agent(output_type=PydanticModel)`, more hand-written routing and state. |

**Measured offline:** The [benchmark](../eda/framework_spike/README.md) ran five Bank Marketing gate scenarios three times each per framework (30 runs). Both returned valid Pydantic handoffs and expected routing in 15/15 runs, with 0/15 run errors. Median wall time was 0.001 s for LangGraph and 0.008 s for the Agents SDK; nearest-rank p95 was 0.004 s and 0.067 s. Imports were warmed before timing. These local HTTP-fixture times are **not** Vertex latency. The scenarios exercise pass, retry, and exhausted-cap paths with predetermined scores; they do not measure GAN evaluation quality. The separate cap-1 and cap-2 tests also passed.

**Live run:** The [README table](../eda/framework_spike/README.md#live-results) compares 13 matched successful case/repeat pairs per framework, excluding two pairs affected by late authentication failures. Both routed 13/13 correctly with 56 reported calls. LangGraph used 7,873 tokens at an estimated $0.021657; the Agents SDK used 8,646 tokens at $0.023784, about 10% more. Median run time was 45.5 s versus 37.6 s. This small, sequential run shows a modest token/cost difference for these prompts, not a reliable latency winner or real GAN-quality result. Raw failures remain in the local JSONL for audit; the benchmark now refreshes ADC between repeats.

**Vertex AI status:** Gemini was reached using ADC and the ignored `eda/framework_spike/.env`; both frameworks produced structured live outputs. No key is committed. Google's OpenAI-compatible endpoint documents structured Chat Completions, and the Agents SDK supports a custom `OpenAIChatCompletionsModel`. [Google compatibility](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/start/openai), [Agents SDK provider setup](https://openai.github.io/openai-agents-python/models/).

For #28, use LangGraph for deterministic routing and Pydantic for stage outputs. Implement its full `log_decision(agent, rule, inputs, outcome, rationale)` schema separately from vendor tracing; the spike's JSONL is intentionally smaller. Add durable checkpoints only when resume across processes is required. Revisit the choice if most future control flow becomes model-selected handoffs. [LangGraph state/edges](https://docs.langchain.com/oss/python/langgraph/graph-api), [Agents SDK tracing](https://openai.github.io/openai-agents-python/tracing/).
